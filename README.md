# GateLogin

**GateLogin** — самостоятельный сервер авторизации для сайтов, приложений, игр и API. Он хранит аккаунты, выдаёт постоянные UUID и управляет секретными токенами доступа.

## Возможности

- Регистрация пользователей через HTTP API.
- Постоянный UUID, который создаётся один раз при регистрации.
- Токен из ровно 255 случайных букв и цифр при каждом успешном входе.
- Один активный токен на аккаунт: новый вход автоматически отзывает предыдущий токен.
- Бессрочный токен: он действует, пока пользователь не войдёт снова или не выполнит выход.
- Проверка токена и отзыв токена.
- SQLite для хранения аккаунтов.
- Пароли хранятся в виде хешей, а токены — в виде SHA-256-хешей.

## Как это работает

1. Клиент отправляет логин и пароль на `POST /login`.
2. GateLogin проверяет пароль.
3. Сервер возвращает постоянный `uuid` пользователя и новый секретный `token`.
4. Клиент передаёт токен в заголовке `Authorization: Bearer <token>` при проверке доступа.
5. При следующем успешном входе предыдущий токен перестаёт работать.

UUID — это идентификатор аккаунта, а не секрет. Для подтверждения доступа используется только токен.

## Установка

Требуется Python 3.9 или новее.

```bash
git clone https://github.com/somerare22-lab/gatelogin.git
cd gatelogin
python -m venv .venv
```

Активируйте виртуальное окружение:

**Linux / macOS**
```bash
source .venv/bin/activate
```

**Windows**
```powershell
.venv\\Scripts\\activate
```

Установите зависимости и запустите сервер:

```bash
pip install -r requirements.txt
python app.py
```

По умолчанию сервер доступен на `http://127.0.0.1:5000`. База данных `gatelogin.sqlite3` создаётся автоматически.

Можно задать параметры окружения:

- `GATELOGIN_DATABASE` — путь к файлу SQLite.
- `GATELOGIN_HOST` — адрес прослушивания (по умолчанию `127.0.0.1`).
- `GATELOGIN_PORT` — порт (по умолчанию `5000`).

## HTTP API

Все запросы с данными принимают JSON.

### Регистрация — `POST /register`

Запрос:

```json
{
  "username": "alice",
  "password": "a-long-password"
}
```

Успешный ответ (`201`):

```json
{
  "uuid": "постоянный-uuid-пользователя",
  "message": "account created"
}
```

Пароль должен содержать от 8 до 256 символов. Имя пользователя — не более 64 символов.

### Вход — `POST /login`

Запрос:

```json
{
  "username": "alice",
  "password": "a-long-password"
}
```

Ответ:

```json
{
  "uuid": "постоянный-uuid-пользователя",
  "token": "255-символьный-секретный-токен",
  "token_length": 255
}
```

Токен показывается клиенту только при входе. Сохраняйте его в защищённом хранилище и не публикуйте.

### Проверка токена — `POST /verify`

Передайте токен в HTTP-заголовке:

```http
Authorization: Bearer YOUR_TOKEN
```

Успешный ответ:

```json
{
  "valid": true,
  "uuid": "постоянный-uuid-пользователя",
  "username": "alice"
}
```

Недействительный, отозванный или заменённый токен возвращает HTTP `401` и `{"valid": false}`.

### Выход — `POST /logout`

Передайте тот же заголовок `Authorization: Bearer YOUR_TOKEN`. Сервер удалит хеш активного токена. После этого токен больше нельзя использовать.

## Пример клиента на Python

```python
import requests

SERVER = "http://127.0.0.1:5000"

login = requests.post(
    f"{SERVER}/login",
    json={"username": "alice", "password": "a-long-password"},
    timeout=10
)
login.raise_for_status()
session = login.json()

print("UUID:", session["uuid"])

headers = {"Authorization": f"Bearer {session['token']}"}
check = requests.post(f"{SERVER}/verify", headers=headers, timeout=10)
print(check.json())
```

## Важные замечания по безопасности

- Не используйте HTTP в публичной сети: разверните GateLogin за HTTPS reverse proxy.
- Не включайте debug-режим на публичном сервере.
- Не отправляйте токены в URL, логи, сообщения или публичные репозитории.
- Доступ к SQLite-файлу должен быть ограничен правами операционной системы.
- Бессрочный токен остаётся действительным до отзыва. Если он утечёт, злоумышленник сможет использовать его до следующего входа пользователя или выхода; предусмотрите процедуру принудительного отзыва.
- В этой версии один аккаунт поддерживает одну активную сессию. Вход с другого устройства заменяет токен предыдущего устройства.
- Перед публичным запуском добавьте ограничение частоты запросов, мониторинг и резервное копирование базы данных.

## Обновление со старой версии

Новая версия использует SQLite вместо `users.json`. Старые записи автоматически не импортируются: пользователям нужно зарегистрироваться заново. Старый JSON-файл с паролями удалён из текущей версии репозитория. Если в нём были настоящие пароли, смените их: удаление файла из последнего коммита не удаляет его из истории Git.
